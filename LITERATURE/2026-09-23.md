## Part B — Implications for SESPy

**1. Pérez et al.: CHALLENGE, then EXTEND.** `leverage_scores()` (network.py:536) is an equal-weight sum z(betweenness) + z(eigenvector) + z(PageRank), and `governance_actor_influence()` depends on it. Nothing in SESPy tells the user whether the top-ranked leverage nodes are robust to that choice. Pérez et al. found their composite was robust to normalisation but **not** to weighting, and that a single component drove the result. The same failure may exist in SESPy. Port both of their checks: (a) **leave-one-component-out**: recompute the ranking with each of the three terms dropped; (b) **weight perturbation**: sample weights (e.g. Dirichlet(1,1,1)) and recompute. Then report rank stability (Kendall τ against the baseline, and how often each node stays in the top-k). This is cheap to compute and fits the "simple SES" goal, because it returns one label per node (*robust / weight-sensitive*) rather than new numbers. It complements the uncertainty-aware leverage feature that has already shipped, which perturbs **edges**. This check perturbs the **metric definition**.

**2. Salmeron & Pueyo: CHALLENGE (to be verified).** `simulate_dynamics()` applies no activation function, so any imported ISA with spectral radius > 1 grows without bound. `laplacian_spectrum()` already calculates `spectral_radius`, so a low-cost guard is to warn when ρ(M) ≥ 1 and offer an optional bounded FCM-style update `x_{t+1} = f(M x_t)` (sigmoid or tanh). Read the paper to see which activations and which convergence conditions it proves before choosing a default. *Tension:* a squashing function changes how Behaviour-Over-Time plots read. Keep linear as the default and make bounded mode opt-in.

**3. Mathias & Anderies, and Vu et al.: EXTEND (to be verified, larger).** SESPy's Monte Carlo already produces trajectory ensembles. A viability-style read-out would report, for user-set bounds on target nodes (e.g. Ecosystem Service ≥ 0), the **share of runs that stay inside the bounds for the whole horizon**. For each candidate intervention, it would report how that share changes. This is a light, sampling-based stand-in for a viability kernel. Check the full texts, and the INRAE code, to see which computation they actually use before designing it. *Tension:* true viability-kernel algorithms are heavy and aimed at low-dimensional continuous models, so the sampling proxy is the only version that fits the simple-SES goal.

**4. Sovatzidi & Iakovidis: VALIDATE (background).** Supports adding explanations to the rule-based and Claude-assisted connection scoring in the 12-step wizard (e.g. showing *why* a link was scored). No concrete method to port until the review has been read.

**5. Szetey et al. and Drustrup et al.: no action.** Confirm the stakeholder CLD → quantified-scenario pathway SESPy already follows.

## Part C — Roadmap (SESPy)

### HIGH
**H1: Leverage-ranking robustness (leave-one-out + weight perturbation)**
- **Target:** `sespy/network.py`, new `leverage_robustness(isa, n_samples=500, top_k=5, seed=None)`, plus one column in the leverage table and report.
- **What to add:** recompute the leverage ranking with each component dropped and under Dirichlet-sampled weights. Return per-node top-k retention frequency and Kendall τ against the baseline, then label nodes *robust* or *weight-sensitive*.
- **Paper:** Pérez et al. 2026, https://doi.org/10.3389/fmars.2026.1880882
- **Effort:** quick. **GitHub issue:** yes (draft appended to `proposed-issues.md`).

### MEDIUM
**M1: Divergence guard + optional bounded (FCM) update in `simulate_dynamics`**
- **Target:** `sespy/dynamics.py`.
- **What to add:** warn when `spectral_radius ≥ 1`, and add an opt-in `activation={"linear","sigmoid","tanh"}`.
- **Paper:** Salmeron & Pueyo 2026, https://doi.org/10.1016/j.neucom.2026.134140 (check the full text first).
- **Effort:** quick. **GitHub issue:** after reading the paper.

**M2: Viability share in the Monte Carlo / intervention panel**
- **Target:** Monte Carlo output in `sespy/dynamics.py` and the intervention module.
- **What to add:** user bounds on target nodes. Report the share of ensemble runs that stay inside the bounds for the whole horizon, per scenario.
- **Papers:** Mathias & Anderies 2026, https://doi.org/10.1016/j.ecolmodel.2026.111726 and Vu et al. 2026, https://doi.org/10.1016/j.ecolmodel.2026.111738 (check the full texts and code first).
- **Effort:** moderate. **GitHub issue:** later.
