## Part B — Implications for SESPy

**1. Geekiyanage et al. — leverage points for fisheries (systems thinking)**
Maps directly onto the existing `leverage` composite `z(betweenness)+z(eigenvector)+z(PageRank)` in `sespy/network.py`. The composite is purely *structural*: it says a node is well-positioned, not *how deep* an intervention on it would be. A systems-thinking leverage framing is ordinal (parameters → feedback → rules → goals → paradigms).
**Verdict: EXTEND.** Add a depth classification alongside the z-score composite. Caveat: abstract unavailable, so treat the classification scheme as motivated-by rather than replicated-from this paper.

**2. Lau & Chan — NEXIS, interaction topology**
Directly CHALLENGES two SESPy assumptions: (a) the adjacency matrix is static across the whole `dynamic simulation` / Monte Carlo run; (b) node states carry the signal. NEXIS claims topology is a first-order property and that state-only models under-perform.
**Verdict: CHALLENGE + EXTEND.** Two separable pieces of work: a cheap diagnostic (compare simulated outcomes for matched node states under perturbed topology) and an expensive one (time-varying edge weights in the linear-matrix iteration).
**Tension with the "simple SES" goal: HIGH.** Time-varying topology is exactly the kind of complexity MarineSABRES asked us not to force on stakeholders. Recommend the diagnostic, defer the dynamics.

**3. Brons et al. — soft systems map of the EU food system**
VALIDATES SESPy's overall posture (build a coarse map, then hunt leverage points). Also names the tension SESPy lives with: complexity vs. practical relevance. Their expert-interview validation step has no analogue in the 12-step AI-ISA wizard.
**Verdict: VALIDATE, plus a possible wizard step for structured expert validation of the elicited map.**

**4. Nguyen et al. — loop dominance shift (R1–R5, B1)**
This is the strongest methodological hit for SESPy. Feedback-loop detection with reinforcing/balancing polarity already exists — but SESPy reports the *inventory* of loops, not which loop **dominates behaviour at a given time**. Nguyen et al.'s core finding is precisely a dominance shift (B1 dominant early, then displaced). SESPy already has Behaviour-Over-Time and matrix iteration, so per-timestep loop gain is computable from existing machinery.
**Verdict: EXTEND — highest-value gap this week.**

**5. Imtihan et al. — CLD polarity mapping, balancing loop as barrier**
VALIDATES the reinforcing/balancing polarity detection SESPy already implements, and supplies an interpretation pattern worth surfacing: *"which balancing loop is suppressing my target outcome?"* That is a query, not a metric — it needs loop-to-target attribution.
**Verdict: VALIDATE + small feature (loop-to-target attribution in the intervention module).**

**6. Zeng et al. — PSR marine indicator framework**
PSR is a close cousin of DAPSI(W)R(M): Pressure ≈ Pressure, State ≈ Marine Process and Function, Response ≈ Measure. A cross-walk export would let SESPy outputs be compared against PSR-based marine assessments.
**Verdict: EXTEND (quick, low-risk interoperability win).**

**7. Newell et al. — Participatory Creative Systems Mapping**
Relevant to the AI-ISA wizard's elicitation front-end rather than to `network.py`. Their contribution is that persona/journey/storyboard scaffolding let non-experts produce a usable CLD.
**Verdict: EXTEND (wizard-side, optional).**

**8. Wang et al. — SES resilience bibliometrics**
No method to port. Scoping/positioning reference for the README and for framing SESPy's resilience outputs against SDG language.
**Verdict: context only.**

**9. Munteanu et al. — legacy effects on bear–human SES**
CHALLENGES the memoryless linear-matrix iteration: an SES state can be driven by a decision taken 60 years earlier. SESPy has no delay or legacy term.
**Verdict: CHALLENGE.** A per-edge lag parameter is the minimal response, but it multiplies the parameter burden — low priority given the "simple SES" constraint.

**10. Uleman et al. — D2D, the canonical citation for a feature already shipped**
VALIDATES `uncertainty_scores()` (closed #4, merged `fa9e212`) at the strongest level available: the Monte-Carlo-over-structural-uncertainty approach SESPy implements is now peer-reviewed method with an open-source package and web app alongside it. No feature gap. Worth citing directly in the README and in the uncertainty module's docstring. That the venue is *BMC Medicine* is itself useful — it demonstrates the method's generality beyond SES.
**Verdict: VALIDATE — add the citation.**

**11. Revay et al. — FCM activation functions**
SESPy imports FCM edge weights (closed #2) but never exposes the activation function on the simulation path. The paper shows that choice materially moves steady states, so the omission is a real if narrow gap. Impact is bounded by the fact that SESPy's core paradigm is signed CLDs, not iterative FCM activation-update cycles.
**Verdict: EXTEND — low priority, FCM import path only.**

**12. ALC — loop-informed leverage**
Weights a node's importance by the loops it participates in (loop strength, and whether the node initiates or reinforces) rather than scoring nodes independently. This is conceptually adjacent to H1 below: both replace time- and loop-blind node scoring with loop-aware structure. SESPy already computes the loop set via `find_loops()`, so the inputs exist.
**Verdict: EXTEND — folded into H1 rather than filed separately (see H1).**

## Part C — SESPy improvement roadmap

### HIGH

**H1 — Loop dominance over time**
*Target:* `sespy/network.py`, new function (e.g. `loop_dominance(G, weights, timesteps)`).
*What to add:* for each detected feedback loop, compute the loop gain (product of signed edge weights around the cycle) at each timestep of the existing linear-matrix iteration and rank loops per timestep, so the Behaviour-Over-Time plot can be annotated with which reinforcing/balancing loop is currently dominant.
*Motivating papers:* [10.1002/sres.70145](https://doi.org/10.1002/sres.70145) (loop dominance shift B1 → R), [10.25105/urbanenvirotech.v9i2.22457](https://doi.org/10.25105/urbanenvirotech.v9i2.22457) (balancing loop as barrier).
*Related formulation — ALC.* The *Adjusted Loop Centrality* metric ([10.1016/j.envsci.2025.103996](https://doi.org/10.1016/j.envsci.2025.103996)) attacks the same blind spot from the node side: it weights a node by the loops it sits in, where H1 ranks the loops themselves over time. Both need the same inputs (`find_loops()` output plus per-node loop membership and a gain measure), so ALC is tracked here as an alternative output of one piece of work rather than as a competing issue. If H1 is implemented, exposing ALC alongside the per-timestep ranking should be nearly free.
*Effort:* moderate — reuses existing loop detection + simulation.
*GitHub issue:* **yes** (covers ALC).

**H2 — Leverage-point depth classification**
*Target:* `sespy/network.py`, extend the leverage composite output with a categorical `leverage_depth` field.
*What to add:* classify each top-ranked node by intervention depth (parameter / feedback-structure / rules / goals-and-paradigm) using its DAPSI(W)R(M) type and its participation in detected feedback loops, reported next to the existing `z(betweenness)+z(eigenvector)+z(PageRank)` score.
*Motivating papers:* [10.1016/j.crm.2026.100843](https://doi.org/10.1016/j.crm.2026.100843), [10.1007/s11625-026-01872-2](https://doi.org/10.1007/s11625-026-01872-2).
*Effort:* moderate.
*GitHub issue:* **yes**.

### MEDIUM

**M1 — Topology-sensitivity diagnostic**
*Target:* `sespy/network.py`, new function alongside the node-ablation/intervention code.
*What to add:* hold node initial states fixed, perturb the edge set (rewire / drop k edges), re-run the Monte Carlo simulation and report outcome divergence — a structure-sensitivity score quantifying how much the result is driven by topology rather than states.
*Motivating paper:* [10.21203/rs.3.rs-10746688/v1](https://doi.org/10.21203/rs.3.rs-10746688/v1).
*Effort:* moderate. *Issue:* optional.

**M2 — Loop-to-target attribution**
*Target:* intervention / node-ablation module.
*What to add:* given a target node (typically a Good and Benefit), list the balancing loops that contain a path into it, ranked by loop gain — answering "which balancing loop is suppressing this outcome?".
*Motivating paper:* [10.25105/urbanenvirotech.v9i2.22457](https://doi.org/10.25105/urbanenvirotech.v9i2.22457).
*Effort:* quick–moderate. *Issue:* optional.

**M3 — PSR cross-walk export**
*Target:* HTML/PDF/Word export layer.
*What to add:* an optional Pressure–State–Response view that maps DAPSI(W)R(M) node groups onto PSR categories, so SESPy output is comparable with PSR-based marine assessments.
*Motivating paper:* [10.3389/fmars.2026.1834331](https://doi.org/10.3389/fmars.2026.1834331).
*Effort:* quick. *Issue:* no.

**M4 — Expert-validation step in the AI-ISA wizard**
*Target:* 12-step AI-ISA wizard.
*What to add:* an explicit map-validation step (structured review of elicited connections by a second respondent) between elicitation and scoring, mirroring the expert-interview validation stage of the soft systems methodology.
*Motivating paper:* [10.1007/s11625-026-01872-2](https://doi.org/10.1007/s11625-026-01872-2).
*Effort:* moderate. *Issue:* no.

### LOW

**L1 — Optional per-edge lag / legacy term**
*Target:* dynamic simulation (linear-matrix iteration).
*What to add:* an optional integer delay per edge so a Driver's effect on a downstream node can be offset by *n* timesteps, representing historical legacy effects.
*Motivating paper:* [10.1007/s13280-026-02453-4](https://doi.org/10.1007/s13280-026-02453-4).
*Effort:* moderate; adds parameter burden — flagged as a tension with the "simple SES" goal. *Issue:* no.

**L2 — Time-varying topology in simulation**
*Target:* dynamic simulation.
*What to add:* accept an edge-weight schedule (per-timestep adjacency) rather than a single static matrix.
*Motivating paper:* [10.21203/rs.3.rs-10746688/v1](https://doi.org/10.21203/rs.3.rs-10746688/v1).
*Effort:* large. Explicitly deferred: it conflicts with the MarineSABRES "simple SES" goal. *Issue:* no.

**L3 — Participatory elicitation scaffolding**
*Target:* AI-ISA wizard front-end / docs.
*What to add:* persona and user-journey prompts as an optional pre-step for non-technical stakeholder workshops.
*Motivating paper:* [10.31234/osf.io/8pcgu_v3](https://doi.org/10.31234/osf.io/8pcgu_v3).
*Effort:* quick. *Issue:* no.
